## 2. 해야 할 일 (순서대로)

### 2-0. 업로드 키 백업 — 지금

`android/keystores/ditto-upload.jks` 와 `android/keystore.properties`(비밀번호가 들어 있다)를 **함께**
팀 비밀 저장소(1Password 등)에 올린다. 둘 다 gitignore 라 이 맥이 사라지면 같이 사라진다.

- 잃어버려도 앱은 살아 있다 — Play 앱 서명이라 사용자에게 가는 서명 키는 Google 이 보관한다. 다만
  업로드 키 재설정을 Play 에 요청해야 하고 처리에 며칠 걸린다.
- 비밀번호는 채팅·문서·커밋에 적지 않는다.

### 2-1. Play Console 개발자 계정

계정이 없으면 <https://play.google.com/console/signup> 에서 만든다(등록비 US$25, 신원 확인 필요).

⚠️ **계정 유형이 출시 일정을 좌우한다.**

| 유형 | 프로덕션 출시 조건 |
|---|---|
| **개인** 계정(2023-11-13 이후 생성) | **비공개 테스트에 테스터 12명 이상이 14일 연속 참여**한 뒤 "프로덕션 액세스 신청"을 해야 한다. 최소 2주+심사 |
| **조직** 계정 | 위 조건 없음. 내부 테스트 → 바로 프로덕션 가능. 대신 D-U-N-S 번호가 필요하다 |

개인 계정이면 2-3 의 비공개 테스트를 **최대한 일찍** 시작한다. 테스터는 Google 계정(Gmail)이 있는 지인 12명 이상이면 된다.

### 2-2. 앱 만들기 · 첫 번들 업로드

1. Play Console → **앱 만들기** — §3-1 값.
2. **테스트 및 출시 → 내부 테스트 → 새 버전 만들기** → `build/android/ditto-1.0-1.aab` 업로드.
   - 처음 올릴 때 **Play 앱 서명**을 묻는다 → 기본값(Google 이 키 생성·관리)으로 둔다.
   - 첫 번들은 Console 에서 손으로 올려야 한다(API 로는 앱 레코드가 생긴 뒤부터 된다).
3. 내부 테스터(최대 100명)에 팀원 Gmail 을 넣고 링크로 설치한다 — 심사 없이 바로 받는다.

### 2-3. 카카오 개발자 콘솔 — Android 키 해시

카카오 네이티브 로그인은 **앱을 서명한 인증서의 키 해시**가 콘솔에 등록돼 있어야 한다. 없으면 카카오톡 로그인이
실패하고 리다이렉트 로그인으로 폴백한다(로그인은 되지만 카카오톡 앱 전환이 안 된다).

내 애플리케이션 → 디토 → 앱 → 플랫폼 → **Android** (기존 앱에 추가 — 새 앱을 만들지 말 것)

| 항목 | 값 |
|---|---|
| 패키지명 | `pics.ditto.app` |
| 마켓 URL | `https://play.google.com/store/apps/details?id=pics.ditto.app` |
| 키 해시 — 업로드 키 | `4Y28m9ib8cG//93cv+VoFVsY42U=` (로컬 릴리스 빌드·내부 앱 공유용) |
| 키 해시 — 디버그 키(이 맥) | `cX2Q268GxPeMiCvT6j+9gXPUsEo=` (Android Studio 실행용) |
| 키 해시 — **Play 앱 서명 키** | ⬜ 2-2 를 마친 뒤 — 아래 |

**Play 로 받은 앱은 Google 의 앱 서명 키로 다시 서명된다.** 스토어·테스트 트랙으로 설치한 앱은 이 해시로만 통한다.
Play Console → 테스트 및 출시 → 설정 → **앱 서명** → "앱 서명 키 인증서"의 **SHA-1** 을 복사해 변환한다
(인증서 지문은 공개 값이라 채팅에 붙여 줘도 된다 — 대신 변환해 준다):

```bash
echo '<SHA-1, 콜론 포함 그대로>' | tr -d ':' | xxd -r -p | openssl base64
```

### 2-4. Play Console 입력 — §3 의 값 그대로

스토어 등록정보 · 앱 콘텐츠(개인정보처리방침·앱 액세스·광고·콘텐츠 등급·타겟층·데이터 보안·계정 삭제 등) · 국가.

### 2-5. 실기기 스모크

런북 §3 체크리스트를 **Android 실기기**로 한 번 돈다. 특히 Android 에서만 깨지는 것:

- 카카오 로그인 — 카카오톡 설치·미설치 두 경우(키 해시가 맞으면 카카오톡으로 넘어갔다 돌아온다)
- 애플 로그인 — Android 는 웹 리다이렉트다. 웹뷰 안에서 끝나고 앱으로 돌아오는지
- 앱을 켠 채 푸시 받기 — 배너가 뜨고 **설정 화면이 열리지 않는지**(웹 배포 뒤에 확인)
- 채팅 입력창 — 키보드가 입력창을 가리지 않는지(Android 는 웹뷰 리사이즈에 맡긴다)
- 하드웨어 뒤로가기 · 사진 첨부 · 장소 지도 위치 권한 · 다크 모드에서 상태바 아이콘이 보이는지

### 2-6. 비공개 테스트 → 프로덕션

- 개인 계정: **비공개 테스트** 트랙에 같은 번들을 올리고 테스터 12명 이상 → 14일 → 프로덕션 액세스 신청.
- 조직 계정: 내부 테스트 확인 뒤 프로덕션 트랙에 올린다.
- 프로덕션 출시 방식은 **수동**으로 둔다(심사 통과 뒤 내가 누를 때 공개). iOS 와 같다.

### 2-7. 출시 뒤 — §6

### 2-8. BE · 운영 확인 (FE 밖)

- **탈퇴 회원 완전 삭제가 실제로 켜져 있는지.** `LeftMemberPurgeService` 는 `ditto.member.purge.dry-run`
  기본값이 `true`(지울 대상을 로그로만 남기고 지우지 않는다)이고, 레포의 `application*.yml` 에는 이 값을 끄는 설정이 없다.
  ECS 작업 정의 환경변수(`DITTO_MEMBER_PURGE_DRY_RUN=false`)로 꺼 두지 않았다면 **"30일 뒤 완전 삭제"가 지켜지지 않는다** —
  Play 데이터 보안·계정 삭제 페이지·탈퇴 화면이 모두 그렇게 말하고 있다.
- **개인정보 처리방침 §4.2(1)과 실제 동작이 다르다.** 방침은 "회원 탈퇴 시 원칙: 즉시 파기"인데, 탈퇴 화면과 BE 는
  "30일 복구 후 완전 삭제"다. 계정 삭제 안내 페이지는 실제 동작(30일)을 적었다. 방침을 30일로 개정할지는 결정이 필요하다.
- Android 출시 알림 신청 API(`docs/be-request-launch-notifications.md`) 배포 · 출시 뒤 신청자에게 안내 메일 발송.

## 3. Play Console 입력값

### 3-1. 앱 만들기

| 항목 | 값 |
|---|---|
| 앱 이름 | **`디토`** (App Store 와 같다. 30자 이내) |
| 기본 언어 | 한국어 – ko-KR |
| 앱 또는 게임 | 앱 |
| 무료 또는 유료 | **무료** — 한 번 무료로 내면 유료로 바꿀 수 없다 |

### 3-2. 기본 스토어 등록정보

**간단한 설명** (80자 이내)

```text
매주 퀴즈 12문제로, 나와 같은 답을 고른 사람을 만나요.
```

**자세한 설명** (4,000자 이내) — App Store 설명과 맞추고 싶으면 App Store Connect 의 설명을 그대로 붙여 넣어도 된다.
아래 원고는 심사 노트(`docs/app-store-submission.md` §3-3)의 사실만으로 썼다. "인증", "검증된 회원" 같은 표현은
쓰지 않는다(본인인증이 없다 — 같은 문서 §6).

```text
디토는 매주 퀴즈 하나로 나와 닮은 사람을 만나는 서비스예요.
프로필 사진 대신 캐리커처를 쓰고, 외모보다 생각이 통하는 사람을 먼저 알아봐요.

■ 이렇게 진행돼요
· 월~수: 이번 주 퀴즈 두 개(1:1 퀴즈, 그룹 퀴즈) 중 하나를 골라 12문제에 답해요.
· 목: 1:1 퀴즈는 나와 같은 답을 많이 고른 사람을 최대 5명까지 보여 드려요. 소개노트를 보고 대화를 신청할 수 있어요. 그룹 퀴즈는 비슷한 답을 고른 3~6명이 한 그룹이 돼요.
· 금~일: 매칭된 사람과 72시간 동안 대화해요. 그룹 대화방에서는 만날 시간과 장소를 투표로 정하고, 주변 장소 지도도 볼 수 있어요. 모든 대화는 일요일 밤 11시 59분에 닫혀요.
· 대화가 끝나면 서로를 평가해요.

■ 안심하고 대화할 수 있게
· 불편한 상대는 대화방이나 평가 화면에서 바로 신고할 수 있어요. 신고하면 자동으로 차단돼요.
· 금칙어가 들어간 메시지는 보내기 전에 한 번 더 확인하고, 링크나 송금 요청이 담긴 메시지에는 주의 안내를 보여 드려요.
· 신고는 운영팀이 24시간 안에 검토해 이용약관에 따라 조치해요.

■ 이용 안내
· 만 19세 이상만 가입할 수 있어요.
· 카카오 또는 Apple 계정으로 로그인해요.
· 문의: ditto.apply@gmail.com
```

| 항목 | 값 |
|---|---|
| 앱 카테고리 | **소셜** (App Store 기본 카테고리 "소셜 네트워킹"과 맞춤). "데이트"도 고를 수 있다 — 결정 필요 |
| 이메일 | `ditto.apply@gmail.com` |
| 웹사이트 | `https://ditto.pics` |
| 개인정보처리방침 | `https://ditto.pics/settings/privacy` |

| 신고 항목 | 답 | 근거 |
|---|---|---|

### 3-4. 데이터 보안

`ios/App/App/PrivacyInfo.xcprivacy` · App Store 앱 개인정보와 **같은 판단**으로 맞췄다. 모든 항목 **공유 = 아니요**
(GA4 는 우리 대신 처리하는 서비스 제공업체라 Play 기준 "공유"가 아니다), **수집 목적에 광고·마케팅 없음**.

**공통 질문**

| 질문 | 답 |
|---|---|
| 필수 데이터 유형을 수집·공유하나요? | 예 |
| 전송 중 암호화 | 예 (HTTPS 만 쓴다) |
| 계정 생성 방법 | OAuth(카카오, Apple) |
| 계정 삭제 요청 방법 | 앱 안(설정 → 회원탈퇴) + 웹 링크 `https://ditto.pics/support/delete-account` |
| 계정은 지우지 않고 데이터만 삭제 요청 | 아니요(별도 경로 없음) — 해당 질문이 나오면 |

**수집하는 데이터**

| 분류 > 유형 | 목적 | 필수/선택 | 무엇 |
|---|---|---|---|
| 개인 정보 > 이름 | 앱 기능, 계정 관리 | 선택 | Apple 로그인이 최초 1회 주는 이름 |
| 개인 정보 > 이메일 주소 | 앱 기능, 계정 관리 | 필수 | 소셜 로그인 이메일 |
| 개인 정보 > 사용자 ID | 앱 기능, 분석, 계정 관리 | 필수 | 회원 ID · 소셜 계정 ID |
| 개인 정보 > 성적 지향 | 앱 기능 | 필수 | 매칭 성별 선호. iOS 에서 "민감한 정보"로 신고한 것과 같은 판단(과소 신고가 더 위험) |
| 개인 정보 > 기타 정보 | 앱 기능 | 필수 | 생년월일·성별·거주 지역·직업·관심사·캐리커처 |
| 위치 > 정확한 위치 | 앱 기능 | 선택 | 그룹 대화 장소 지도 |
| 위치 > 대략적인 위치 | 분석 | 필수 | GA4 가 IP 로 추정하는 지역 |
| 메시지 > 기타 인앱 메시지 | 앱 기능 | 필수 | 채팅 |
| 사진 및 동영상 > 사진 | 앱 기능 | 선택 | 채팅·신고 첨부 |
| 앱 활동 > 앱 상호작용 | 분석 | 필수 | GA4 화면·이벤트 |
| 앱 활동 > 기타 사용자 제작 콘텐츠 | 앱 기능 | 필수 | 퀴즈 답변·소개노트·평가·신고 내용 |
| 기기 또는 기타 ID | 앱 기능, 분석 | 필수 | FCM 등록 토큰 · GA 클라이언트 ID |

수집하지 않음: 금융 정보, 건강·피트니스, 연락처, 캘린더, 파일 및 문서, 웹 검색 기록, 앱 정보 및 성능(비정상 종료 로그·진단 — Crashlytics 없음), 오디오.

### 3-5. 콘텐츠 등급 (IARC 설문)

| 질문 | 답 |
|---|---|
| 카테고리 | **소셜 네트워킹, 포럼, 블로그, UGC 공유** |
| 사용자끼리 소통하거나 콘텐츠(텍스트·이미지)를 주고받을 수 있나요? | **예** |
| 사용자가 다른 사용자에게 자신의 실제 위치를 공유할 수 있나요? | 아니요 (장소 지도는 내 위치를 남에게 보내지 않는다 — 고른 장소만 투표로 공유) |
| 디지털 상품 구매 | 아니요 |
| 폭력·성적 콘텐츠·욕설·약물·도박(앱이 직접 제공하는 콘텐츠) | 아니요 |
| 사용자 신고·차단 기능 | 예 |

등급은 설문 결과로 정해진다. 결과와 무관하게 **타겟층(§3-3)을 18세 이상**으로 둔다.

### 3-6. 앱 액세스 — 심사용 로그인

리뷰어는 카카오·애플 인증을 대신 통과할 수 없다. **로그인 첫 화면 로고를 5번 누르면 심사용 로그인**이 열린다
(`ReviewLogin.tsx`, BE ditto-server #305). Android 에서도 그대로 동작한다.

- 이름: `Review login`
- 사용자 이름 · 비밀번호: BE 에 설정된 심사 계정 값 — **Play Console 에만 입력하고 채팅·문서·커밋에 남기지 않는다**
- 기타 안내(그대로 붙여넣기):

```text
Tap the "ditto" logo on the first screen 5 times to open the review login, then sign in with the ID and password above.
Matches and chat rooms are only created on a weekly schedule (quiz Mon-Wed, matching Thu, chat Fri-Sun), so a new account shows empty results. The review account already has matching results and chat rooms.
```

대화방은 금~일에만 열려 있다 — App Store 때처럼 **목~토에 심사를 넣는 것**이 안전하다(`app-store-submission.md` §3-5).

## 6. 출시 뒤

1. **다운로드 화면에 Google Play 버튼을 켠다** — `.github/workflows/deploy-prod.yml` 의 deploy 잡 Build 스텝 `env:` 에
   `NEXT_PUBLIC_PLAY_STORE_RELEASED: 'true'` 를 넣고 배포한다. 출시 알림 신청 버튼이 Google Play 버튼으로 바뀐다.
   **프로덕션 공개가 끝난 뒤에** 켠다 — 그 전에는 Play 주소가 "찾을 수 없음"이다.
2. 출시 알림 신청자에게 안내 메일(BE 어드민 CSV) → 발송 완료 표시.
3. `app-store-submission.md` §3-6 처럼 **심사 중에는 프로덕션 웹 배포를 멈춘다** — 앱이 `ditto.pics` 를 그대로 띄운다.
